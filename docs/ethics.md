# Ethical Guidelines

ResiMantle is fundamentally a **defensive** tool. Its purpose is to protect systems, not attack them.

To maintain trust and professional integrity, the ResiMantle project adheres to the following ethical rules:

1. **No Exploit Generation**: The system will not generate functional exploits or attack payloads.
2. **No Offensive Automation**: The tool will not automate intrusion against external systems.
3. **No Retaliation ("Hack Back")**: ResiMantle will never attempt to attack the origin of an incoming threat.
4. **No External Harm**: The system will not perform actions that damage external infrastructure.
5. **Data Privacy First**: ResiMantle does not collect unnecessary private data and does not phone home telemetry by default.
6. **Strictly Non-Invasive**: ResiMantle will never modify the original source code of the project it is protecting.
7. **Total Transparency**: ResiMantle will not hide its actions from the project owner. Every decision must be auditable.
8. **Explainability**: If an action is blocked, the system must be able to explain *why* in clear terms.
9. **No "Security by Obscurity" Reliance**: While ResiMantle uses decoys and canaries, its core security model relies on observable behavior and strict policy enforcement, not merely hiding flaws.
10. **Open Source Commitment**: The core defensive engine remains open source so the community can audit and improve the defenses.
